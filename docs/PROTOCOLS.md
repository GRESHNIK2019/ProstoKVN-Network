# Протоколы ProstoKVN Network

Этот документ фиксирует **не просто список поддерживаемых ссылок**, а правила,
по которым ProstoKVN Network разбирает, проверяет, тестирует и запускает каждый
тип узла. Цель — чтобы изменение одного протокола не ломало остальные.

## Общий pipeline

Любой узел проходит одинаковые этапы:

1. **Парсинг подписки** → `Node` без запуска внешних процессов.
2. **Структурная валидация** → адрес, порт, UUID/пароль, TLS/REALITY,
   transport и протокольные ограничения.
3. **Выбор ядра** → `protocol_engine.choose_engine()`.
4. **Проверочный SOCKS** → узел сначала поднимается локально без TUN.
5. **HTTPS x3 + TCP + UDP test** → FAIL-узел не выбирается автоматически.
6. **Запуск TUN** → успех только после появления реального
   `prostokvn_network_tun`.
7. **Health monitor** → исчезновение TUN несколько проверок подряд завершает
   сессию перед безопасным reconnect.
8. **Stop/Exit** → завершается дерево xray/sing-box и удаляется runtime config.

Секреты и transport-параметры не «угадываются». Если профиль противоречив,
лучше показать понятную ошибку конкретного узла, чем молча запустить другую схему.

## Матрица

| Протокол | Основное ядро | Transport / сеть | Security | UDP | Особенности |
|---|---|---|---|---|---|
| VLESS | Xray; sing-box fallback для совместимых transport | RAW/TCP, WS, gRPC, XHTTP, HTTPUpgrade и др. | none, TLS, REALITY | зависит от transport/сервера | XHTTP идёт через Xray; Vision ограничен RAW/TCP + TLS/REALITY |
| VMess | sing-box | V2Ray transports из профиля | TLS по профилю | зависит от профиля | UUID обязателен |
| Trojan | sing-box | TCP/V2Ray transports из профиля | обычно TLS | зависит от transport | пароль обязателен |
| Shadowsocks | sing-box | TCP+UDP | шифрование SS | да | проверяется метод шифрования и SIP002/SIP003 данные |
| Hysteria2 | sing-box | QUIC | TLS | да | пароль, SNI/ALPN, bandwidth, obfs; для закреплённого 1.13.14 — salamander |
| TUIC | sing-box | QUIC | TLS | да | UUID+пароль, congestion control, UDP relay mode |

## VLESS

VLESS — наиболее вариативный протокол в проекте, поэтому его обработка вынесена
в единый Xray builder. Один и тот же builder используется и при тесте узла, и
при рабочем Xray bridge.

### Что сохраняется из подписки

- UUID;
- `flow`;
- `encryption`;
- transport (`raw/tcp`, `ws`, `grpc`, `xhttp`, `httpupgrade`);
- path;
- Host / headers;
- gRPC `serviceName` и authority;
- XHTTP mode / extra;
- TLS SNI, ALPN, fingerprint, allowInsecure;
- REALITY public key, short id, SNI, fingerprint, spiderX.

Параметры восстанавливаются одинаково из:

- `vless://` share-link;
- Clash YAML, включая `ws-opts`, `grpc-opts`, `xhttp-opts`, `reality-opts`;
- sing-box JSON с вложенными `transport` и `tls`.

### Xray compatibility

Builder сразу создаёт традиционные поля:

- `streamSettings.network`;
- `realitySettings.publicKey`.

Runtime monkey-patch больше не используется. Это исключает ситуацию, когда
node tester и рабочий VPN получают разные Xray-конфиги.

### XTLS Vision

`xtls-rprx-vision` проверяется до запуска. В ProstoKVN Network он допускается
только с обычным RAW/TCP transport и TLS/REALITY. Профиль Vision поверх WS/gRPC
не запускается как будто он корректный.

### XHTTP

XHTTP считается Xray-specific transport в текущей проверенной конфигурации.
Если Xray недоступен, такой узел получает понятный статус вместо неудачной
попытки передать XHTTP в неподходящее ядро.

## VMess

VMess передаётся sing-box в нормализованном outbound. Проверяются:

- корректный UUID;
- server/port;
- transport/TLS, которые были получены из подписки.

Тест выполняется тем же способом, что и для остальных sing-box узлов: локальный
SOCKS → HTTPS/TCP/UDP → обязательный cleanup.

## Trojan

Обязателен пароль. TLS-параметры и V2Ray transport сохраняются из подписки.
Профиль без TLS не запрещается жёстко, потому что возможны специальные схемы,
но помечается предупреждением: это сигнал проверить источник конфигурации.

## Shadowsocks

Валидатор знает современные AEAD/2022 методы и legacy-методы, которые ещё могут
встречаться в старых подписках. Неизвестный cipher не передаётся ядру вслепую.

Поддерживается базовая логика SIP002. Если подписка содержит plugin, параметры
не должны теряться во время нормализации.

## Hysteria2

Hysteria2 работает напрямую через sing-box и ориентирован на QUIC/UDP.
Проверяются:

- пароль;
- обязательный TLS;
- SNI / ALPN / insecure из профиля;
- bandwidth-поля, если они заданы;
- obfs.

Для закреплённого sing-box `1.13.14` безопасная матрица ProstoKVN Network
ограничивает obfs типом `salamander`. Возможности, добавленные более новыми
sing-box, должны включаться только одновременно с обновлением проверенной версии
ядра и тестовой матрицы.

## TUIC

TUIC работает напрямую через sing-box. Проверяются:

- UUID;
- пароль;
- обязательный TLS;
- `congestion_control`: `cubic`, `new_reno`, `bbr`;
- `udp_relay_mode`: `native`, `quic`.

0-RTT не считается фатальной ошибкой, но помечается предупреждением из-за
replay-риска. Приложение не должно включать 0-RTT самостоятельно.

## TLS / REALITY

Общие правила:

- `insecure` используется только если это явно пришло из подписки;
- SNI не заменяется произвольным доменом;
- fingerprint сохраняется;
- ALPN сохраняется списком;
- REALITY без public key считается некорректным профилем;
- ProstoKVN Network не генерирует новые ключи REALITY вместо отсутствующих.

## Проверка UDP

Наличие живого процесса ещё не означает, что протокол пригоден для игры/голоса.
После подъёма локального SOCKS выполняется SOCKS5 UDP ASSOCIATE и DNS-запрос.
Результат хранится отдельно от HTTPS latency и влияет на score.

Поэтому узел может быть:

- полностью рабочим;
- рабочим по HTTPS, но без UDP;
- нестабильным по HTTPS;
- неподдерживаемым по конфигурации;
- полностью FAIL.

## Ошибки одного узла не валят подписку

Некорректный UUID, неизвестный cipher, отсутствующий REALITY key или
неподдерживаемый transport должны сделать FAIL **только этот Node**. Остальные
узлы подписки продолжают тестироваться.

## Версии ядер

Приложение использует закреплённые проверенные версии, а не `/latest`:

- sing-box: `1.13.14`;
- Xray: `26.7.28`.

Автоматическая установка идёт в версионированные каталоги. Новая версия никогда
не заменяет на месте каталог, из которого прямо сейчас может работать процесс.
Это одновременно даёт воспроизводимость конфигов и устраняет Windows file-lock
ошибки при обновлении.

## Когда добавлять новый протокол/transport

Новый вариант считается поддержанным только когда одновременно есть:

1. parser/normalizer;
2. validator;
3. явный engine plan;
4. unit-test конфигурации;
5. реальный Windows test node;
6. проверка Start → Stop → повторный Start;
7. проверка выхода через tray без orphan-процессов;
8. проверка Smart/Applications/Global.

До выполнения всех пунктов вариант лучше показывать как «не поддерживается»,
а не отправлять в ядро наугад.

## Официальные спецификации

При изменении протокольной логики источником истины должны быть официальные
документации Xray-core и sing-box, а не примеры случайных клиентов:

- Xray / Project X: VLESS outbound и transport documentation;
- sing-box: VLESS, Trojan, Shadowsocks, Hysteria2, TUIC, TLS и V2Ray Transport.

Любое обновление pinned core должно сопровождаться повторным прохождением всей
матрицы выше.
